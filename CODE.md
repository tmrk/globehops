Comparison editing uses `src/state/compare.ts`: one to four journey drafts with stable React keys and positional letters A–D. App delegates existing route actions to the active draft (a new draft starts empty and shows `src/data/similarRoutes.ts` suggestions until it has an airport), computes every journey with `lib/compare.ts`, and serializes A with the classic parameters and alternatives with `b.`, `c.` and `d.` prefixes. `lib/compareView.ts` owns shared-axis bar segments, deduplicated globe routes and local/global leg mapping. `JourneyTabs` provides keyboard tab navigation; `CompareSummary` and `ComparisonStrip` present the ticket. `ComparisonLanes` renders the live statuses. `TimeBar` subscribes narrowly to the one clock and shows each journey's live lane; its range, flight jumps and clock menu cover all journeys. The fleet feed keeps the active journey primary for camera follow. Link/view flight numbers refer to A; live `select_flight` targets the active journey. Single-journey editing and links retain their existing behaviour.

## Conventions

Strict TypeScript; pure calculations separate from React/Three.js effects. Prettier uses single quotes and a 120-column width. CSS stays in the existing token-based stylesheet. Node scripts, the local MCP adapter and all modules they import use erasable TypeScript with `.ts` imports; keep Vite asset imports and module-scope DOM effects out of shared modules. See [AGENTS.md](AGENTS.md) for verification and contribution rules.

## Decisions

**Design language.** Corners are crisp, like airport signage and departure boards, and come from six role tokens in `app.css`: `--radius-sm` (0, square) for rows, fields, options and tabs, `--radius-xs` (2px) for tags, badges, split-flap code tiles and bars, `--radius-btn` (4px) for text buttons and button-like fields, `--radius-md` (6px) for menus and toasts, `--radius-lg` (12px) for panels, sheets and dialogs, and `--radius-full` only for naturally round things: icon buttons, floating globe controls, dots, switches, slider thumbs and rules. Compact panel controls share `--control-h`, floating globe controls `--float-h` with `--surface-float`/`--shadow-float` (`.float-btn`, or `.float-group` for a capsule of buttons whose hover and open states fill each whole segment, the end ones inheriting the capsule's radius). Don't add literal radii.

**Layout and alignment.** Every itinerary row (stop, flight, layover, action) is the same four-column grid: route line (`--col-rail`), airport code (`--col-code`), text, trailing tools, separated by `--col-gap` inside `--pad`. Small icons sit centred in the code column, so codes, icons, names and figures each form one vertical line. Each row draws its own half of the route line (`Rail`), so the line never breaks around editors. Hover and selection backgrounds extend 8px beyond the columns without moving content. Everyday rows carry no management icons: Edit mode reveals reorder, remove and insert, plus Reverse and Clear. The panel has one primary action (amber Play beside the totals); map settings live in the display menu, alongside a separate language button; on phones the timeline docks into the sheet instead of floating as a second card. Airport codes are split-flap tiles, the clearest nod to a departure board.

**Typography.** Two OFL families with distinct jobs, set up as tokens in `app.css`. Barlow, a grotesque drawn from public signage, sets the interface; Martian Mono, narrowed to 78 % of its width (`--mono-stretch`, re-applied after every mono `font` shorthand, which resets it), sets what a departure board would show: airport codes, clock times, dates, distances and totals. Sizes come only from the `--text-*` scale; caps labels use `--track-caps`, codes `--track-code`; mono runs tighten word spacing (`--mono-space`) so “979 km” doesn't gap. The mark is a globe with one great-circle hop using the globe's own origin/destination markers (`public/logo.svg`, a bolder `favicon.svg`, `Brand.tsx`).

**Direct Three.js.** The renderer needs true spherical interpolation and render-on-demand control. The globe.gl/three-globe approach brings h3-js and unused layers, a continuous rendering model and Bezier arcs that can exaggerate height or pass through Earth near antipodes. Direct Three.js keeps these choices explicit; those alternative packages are not dependencies of this project.

**Route geometry and labels.** Unit-vector slerp determines the ground track. The airborne arc follows a simplified climb–cruise–descent profile with one cruising altitude for every flight; height is exaggerated 12× because true altitude is under a pixel at globe scale, while horizontal climb/descent distances stay true. `LineMaterial` keeps screen-space line widths, with `geometry.instanceCount` revealing segments and the last visible segment shortened to the exact progress. Translucent lines use one stencil value each so overlapping segment joints never bead; there is no dashed ground track. HTML labels remain crisp and easy to position; projection hides far-side markers and tries alternate offsets to reduce collisions.

**Framing.** A deterministic enclosing spherical cap includes sampled ground tracks. The camera uses the available field of view after UI insets, label/arc margins and an overview distance limit. Routes that cannot fit show a “Step through flights” stepper instead of implying the entire route is visible. Framing views a route from slightly nearer the equator so great circles show their poleward bow rather than collapsing into a straight line. A view offset centres the scene in the unobstructed area.

**Follow camera.** Aircraft follow is an explicit timeline toggle, separate from the simulation feed’s active-leg framing for routes too wide to fit. `followCamera.ts` supplies phase-based zoom, bounded predictive lead and exponential smoothing independent of frame rate. The renderer stays north-up (`camera.up = +Y`) with the OrbitControls target at the origin, so manual handoff is seamless; avoid heading roll or an offset target. Drag, wheel, touch and keyboard camera input exit aircraft follow. Reduced motion uses occasional immediate re-centering (“page turns”) when the aircraft leaves the safe centre area, without continuous pursuit. The user preference is `globehops:followAircraft`; `follow=1` / document `view.follow` can override it for a visit.

**Time and distance.** Spherical Earth radius is 6,371.0088 km. Estimated minutes are distance / 850 km/h × 60 + 30, rounded to five minutes per leg; distances below 1 km have no estimate. Each transfer adds a layover (default 90 minutes, changeable per stop from a menu of 30 minutes to three days; links may carry any whole minute up to a week). Totals show flying time, layover time and their sum. Winds, aircraft, actual routing and schedules are outside the model.

**Borders.** Natural Earth 1:50m land boundaries are a public-domain, de facto reference that is small enough (35 KB gzipped) to fetch lazily. They are drawn as screen-space `LineSegments2` with stencil-based single blending; coastlines come from the imagery.

**Internationalisation.** `useI18n()` supplies typed `t` keys and locale-aware `fmt` helpers; every UI message belongs in all three catalogues (English, Hungarian, Swedish), with missing keys rejected by TypeScript. English ships in the initial bundle; hu/sv catalogues load lazily. Detection is locale path → `?lang=` → `globehops:locale` → browser time zone (Budapest/Stockholm as country proxies) → browser languages → English. This is not physical geolocation. Language/About selectors save an explicit choice; agent/link locale changes are visit-only. Vite emits crawlable `/en/`, `/hu/`, `/sv/` pages under the configured base, with translated metadata, canonical/hreflang and structured data. Ordinary Share links remove locale paths and `lang`, allowing recipients their own language; explicit agent links may request a locale. Agent/MCP prose remains English and preserves original dataset city names.

**Country, ocean and sea names.** The optional layer has independent “Country names” and “Oceans and seas” visibility and uses Natural Earth countries and marine polygons (242 countries, 7 ocean regions and 72 seas), with larger blue italic ocean caps and smaller italic seas; airport labels keep collision priority. Country/marine text switches locale without another download. `places:build` matches populated places conservatively by normalized name/alias, country and distance (75 km); ambiguous matches are skipped. `data/place-names.json` carries justified label/city overrides; `data/PLACE_NAMES.md` records them and the 54.3% automatic scheduled-airport coverage. `fmt.city()` localizes city displays and search uses additive exonyms; missing names retain original text and airport proper names remain untranslated. The city table loads once on first hu/sv use, never for an English-only visit. The “Country names” preference retains `globehops:countryNames` for compatibility; `globehops:waterNames` initially inherits it. Visit-only `names` overrides both layers; serialization/tool view retains the country value.

**Search.** Match quality plus importance ranks suggestions. Exact ICAO/IATA, city and name prefixes, keywords and token prefixes have different weights; scheduled service, airport size and IATA presence add importance. A short primary-airport hint set breaks major-city ties; its comments explain the policy. It is not a traffic dataset or a guarantee that every city query ranks airports by passenger count.

**URLs and storage.** `?route=CPH-LHR-JFK` uses IATA, then ICAO/ident, with a numeric OurAirports ID for identifiers unsafe in the URL format. A custom layover follows its transfer airport in minutes (`LHR_180`); default layovers and layovers at the first/last stop are omitted. Tokens travel with their stop, so reversing or reordering keeps layovers with the airport, and unknown codes cannot misalign them. Parsing accepts several separators and caps at ten stops. Unknown codes produce a toast while valid stops survive. URL > remembered route determines startup; with neither, the route starts empty and the app opens on the globe and its clock (on phones the sheet starts collapsed under **Show a flight**; `opensWithRoute` decides before data loads). `src/data/suggestions.ts` maps the browser time zone to a likely gateway using legacy aliases, explicit gateway overrides, city search and the airport zone table, with LHR as the fallback. Nothing waits for the zone request; suggestions update when it settles. Three deterministic single-flight previews favour distinct regions, estimates of at least 12 hours and distances no greater than 16,500 km; sparse datasets relax the duration minimum. A chosen suggestion is the visitor's journey (Edit, Share, Reset, Compare). Suggestions remain visible for an empty route or a route that still is one of them (derived, with that suggestion pressed); editing ends the welcome. Explicit `?route=` loads an empty route; canonical empty URLs omit the parameter. Route edits use `history.replaceState`; the mobile picker adds a temporary history entry so Back dismisses it. Navigation between shared URLs loads their routes. Preferences and remembered journey keys are prefixed `globehops:`; `lastJourney` stores a canonical query without `t`, `play` or `units`, with `lastRoute` as a legacy fallback.

**Time zones.** Build-time point-in-polygon lookup against pinned timezone-boundary-builder data produces a small airport-to-IANA table. Runtime `Intl.DateTimeFormat` supplies historical offsets and DST rules; there is no Temporal polyfill or shipped polygon database. Formatter caching keeps repeated conversion cheap. Runtime tzdb versions may differ; mapping a zone does not freeze its rules. The ODbL table remains separate from public-domain airport data.

**Schedule storage and propagation.** Facts belong to stops: each arrival, departure and fallback layover has one home, while the editor presents a flight's departure and arrival together. Insertion/reordering carries times with stops; reversing clears times. `computeJourney` preserves resolved entered anchors, propagates forward with flight estimates and layovers, then fills unknowns backwards. An explicit assumed start can anchor an undated journey. Derived points carry `estimated` or `assumed` provenance; independently anchored endpoints can produce `mixed` durations. Chronology errors prevent playback. See [time and simulation](docs/TIME_AND_SIMULATION.md) for rules and issue codes.

**Flight progress.** Elapsed time maps piecewise linearly to climb, cruise and descent distance using the altitude model's average speeds. Short flights scale climb/descent to fit; longer flights reserve at least 20% of duration for cruise if those phases need compression. Great-circle distance progress is monotonic. The entire departure-to-arrival interval is treated as flight, without separate taxi phases; altitude and track are illustrative.

**Solar model and alignment.** NOAA/Meeus apparent solar coordinates compute declination and equation of time from UTC, giving a date-aware Earth-fixed subsolar point; geometric elevation excludes atmospheric refraction. `sunDirectionScene` uses the same Y-north, +X-Greenwich, −Z-east conversion as airport markers and the texture. Independent astronomy-engine tests across 1900–2100 measured maximum errors of 0.003039° declination, 0.016407° subsolar longitude and 0.014915° elevation; these are sampled numerical errors, not observed-sunrise guarantees. Tests also check scene/texture/marker alignment. astronomy-engine is absent from production calculations.

**Sun and Moon.** With shading on, both appear at true directions and apparent sizes as seen from the camera (`skyBodies.ts`, from `sky` in each simulation frame). The Moon is a real sphere at its real distance, inside the camera's far plane, so perspective supplies size and parallax and Sun-direction lighting supplies the phase; Lommel–Seeliger scattering keeps the full Moon flat, and its shader darkens it in Earth's shadow cones and adds earthshine scaled by Earth's phase as seen from the Moon (brightest near new Moon), a display choice that keeps thin crescents findable. Small HTML labels name the Sun and Moon while on screen, with **Country names** on (they are place names too), placed outwards from Earth's projected centre and flipped inwards at the screen's edge. Because the true-size Moon is in view from only a narrow band of camera directions, **Find the Moon** (display menu, while shading is on) flies to `moonVantage`: on Earth's far side from the Moon, raised north until the Moon stands 2.5° clear of the glowing limb within the available field of view, keeping the north-up camera. The Sun is a camera-facing quad placed at infinity in the vertex shader (direction rotated with `w = 0`), sized to its angular radius; its glare is a display choice outside that radius. `lib/moon.ts` is a compact Meeus ephemeris tested against astronomy-engine (position 0.04°, libration 0.1°), with orientation from Cassini's laws in the same ecliptic-of-date frame, so no precession bookkeeping is needed. The 512 × 256 LROC map loads lazily through `GlobeTextures`.

**Time dial and Live.** Without flights, `TimeDial` is the globe's clock: an hour tape under a fixed needle (drag with momentum, wheel, keys), and a head of three columns — time and clock-zone menu on the left, the date centred (its year only away from the current one), Live on the right. While Live, the dial shows seconds and asks the clock for 1-second ticks; they fold away as soon as the time moves. Live ticks land on the wall clock's own boundaries (whole seconds, half minutes), so displayed seconds turn over with the device's. With dated journeys, the timeline's Live follows the wall clock every second (`TRACKING_TICK_MS`) and turns on the aircraft camera; the ambient globe keeps a 30-second cadence. On phones the dial is part of the collapsed sheet only: opening the planner hides it. Without a route, the globe fills the unobstructed area (`EMPTY_GLOBE_FILL`) and resizes with the panels until the visitor zooms it. One `LiveButton` serves both, styled like a broadcast badge with the `--live` token. Live writes `live=1` instead of `t`.

**Day/night shading.** `sun.ts` owns the CPU daylight curve and generates `SOLAR_SHADING_GLSL` for both Earth and atmosphere. It is one `smoothstep` in sin(elevation) centred exactly on standard sunrise/sunset (−0.833°), ±3° (`TERMINATOR_HALF_WIDTH_DEG`): night from about −3.8°, full day from about +2.2°, a deliberately narrow, legible twilight band. Lambertian direct irradiance falls with solar elevation; diffuse fill and a roughly 6% night floor preserve legibility. Black Marble city lights fade in from −3° to civil dusk at −6°. The curve is a display approximation on a sphere, without weather or terrain. `onBeforeCompile` shares sun-direction/blend uniforms without rebuilding a terminator mesh. Null illumination restores camera-relative lighting; toggling blends over 360 ms unless reduced motion is active.

**Links and itinerary documents.** Share-link v1 extends legacy route tokens with airport-local `depN`/`arrN` and UTC view time, speed, clock, units, shading, aircraft follow, language, map layers and one-based flight selection. A v1 itinerary document offers a strict JSON representation, encoded as base64url in `itinerary`; a valid document takes precedence over readable parameters. Structural checks are separate from airport/time/chronology validation. Oversized itinerary documents can fall back to a usable readable URL. Explicit link/tool view overrides apply to the visit without overwriting saved preferences. Preserve existing links when adding fields; incompatible document changes need a new version. App debounces paused `t` updates and never writes playback frames to history (Safari throttles `replaceState`).

**Shared agent contract.** `src/agent/contract.ts`, itinerary syntax and `schema.ts` supply the vocabulary and schema consumed by links, discovery and MCP. `plan.ts` reuses the browser's decoding, search, schedule, timeline and sun modules. Generate `public/agent/*.json` with `agent:build`; drift is a test failure. Vite emits current freshness metadata separately as `agent/dataset.json`.

**Local MCP and browser tools.** `mcp/` loads checked-in datasets and exposes five tools, four resources and a `plan_and_visualize` prompt over stdio, using the same planning functions. Visualisation results include readable/document URLs and a human summary. Optional experimental WebMCP registers five validated live tools (`get_journey`, `set_route`, `set_view`, `select_flight`, `get_share_link`) only when supported. `useWebTools` feature-detects modern and legacy APIs, aborts/unregisters on cleanup, and isolates API failures from route editing. The MCP SDK and Zod dependencies are tooling dependencies outside the web bundle. GitHub Pages hosts static discovery files, not a server endpoint. [Agent integration](docs/AGENT_INTEGRATION.md) is the external consumer guide.

**Motion and location.** `lib/motion.ts` combines nullable `globehops:reduceMotion` with the system setting; bootstrap and App set `html[data-motion]` for CSS, and all animation consumers use the effective value. The display switch overrides either direction. `useGeolocation` owns a browser watch and its cleanup; `globehops:myLocation` stores only on/off. Positions stay in memory and flow only to the renderer's decorative, occluded blue dot, beneath airport labels. Denial saves off; temporary errors before a fix stop watching without forgetting on. No position enters links, analytics, storage or tools.
